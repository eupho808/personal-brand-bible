# Writing Guide

> How to write everything in the ecosystem.

This document defines the voice, style, and structure for all written materials: README files, case studies, LinkedIn, CV, blog posts, commit messages, and university applications.

---

## Voice

- Clear and direct.
- Confident but humble.
- Personal when telling a story.
- Professional but never corporate.
- Honest about limitations.

---

## Tone by Channel

### README Files

Technical but human. Focus on problem, solution, and usage. No marketing.

### Case Studies

Narrative. Show process, decisions, and learnings. First person allowed.

### LinkedIn

Professional. Connect projects to broader ideas. Share learnings, not just announcements.

### CV / Resume

Concise. Results-oriented. Use active verbs. One page preferred.

### Motivation Letters

Personal. Connect your story to the program. Show why you fit.

### Blog Posts

Honest and specific. Avoid generic advice. Write about what you actually learned.

### Commits

Imperative mood. Under 50 characters. Explain why in the body if needed.

---

## Universal Rules

### Do

- Use short sentences.
- Use active voice.
- Show the problem before the solution.
- Use specific examples.
- Be honest about status and limitations.
- Write for a smart but busy reader.

### Do Not

- Use clichés: revolutionary, game-changing, cutting-edge, leverage, synergy, disruptive.
- Use superlatives without proof: best, most comprehensive, ultimate, first.
- Use filler phrases.
- Write about university admission as the reason for a project.
- Use hype or exaggeration.

---

## Forbidden Phrases

- "This project was built for my portfolio."
- "This project was created for university admission."
- "In today's rapidly changing world..."
- "Leveraging the power of AI..."
- "Revolutionary / game-changing / cutting-edge"
- "The most comprehensive..."
- "The ultimate..."
- "Next-generation..."

---

## Language

- **English only** for public materials.
- Natural phrasing. Avoid translated-sounding structures.
- Use contractions where appropriate: "I don't", "it's".
- Avoid overly formal or academic language.

---

## Formatting

### Headings

- Title case for H1 and H2.
- Sentence case for H3 and below.
- Use ATX style: `#`, `##`, `###`.

### Lists

- Dashes `-` for unordered lists.
- Numbers `1.` for ordered lists.
- Keep list items parallel.

### Code

- Use fenced code blocks with language tags.
- Keep examples short and runnable.

### Links

- Descriptive link text.
- Avoid raw URLs in body text.

## Commit Messages

Use conventional commits:

```
feat: add user authentication
fix: resolve login redirect issue
docs: update installation guide
refactor: simplify dashboard layout
test: add unit tests for parser
chore: update dependencies
```

Rules:

- Imperative mood: "add", not "added".
- Summary under 50 characters.
- Body optional, used for explanation.

---

## LinkedIn Writing

- Headline: position + focus.
- About: personal story + current projects + philosophy.
- Posts: one idea, short, specific.
- Featured: best projects only.

---

## CV Writing

- One page.
- Clear heading with positioning.
- Summary aligned with personal narrative.
- Projects with measurable outcomes.
- Skills focused on product, design, and AI tools.

---

## University Application Writing

- Be specific about why this program.
- Connect your projects to your goals.
- Show long-term thinking.
- Avoid templates.
- Proofread carefully.

---

## Review Checklist

Before publishing any text:

- [ ] No forbidden phrases
- [ ] Active voice where possible
- [ ] Specific examples included
- [ ] Honest about limitations
- [ ] Consistent tone for the channel
- [ ] Proofread
- [ ] Matches the brand voice
